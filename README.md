# งานตัดหญ้า (เว็บหลายบริษัท) · ติดตั้งใหม่ทั้งหมด

มีครบ: สมัคร/เข้าสู่ระบบ · หลายบริษัท (หัวกระดาษ โลโก้ แยกข้อมูลกันที่ฐานข้อมูล) · ทะเบียนสายทาง แขวงและหมวด · งวด (แผนก่อน ใบสั่งจ้างทีหลัง) และใบสั่งจ้าง (Claude อ่าน PDF ให้) · รูปรายงานตาม กม. · PDF รายงานภาพถ่าย ใบสรุปงวด ชุดส่งงวด · ใบเสนอราคา หนังสือส่งมอบงาน ใบกำกับภาษี/ใบเสร็จ · บันทึกรายวัน คนงานและค่าแรง น้ำมัน · ย้ายข้อมูลจากระบบเดิม · บทบาทและสิทธิ์ 5 แบบ

เครื่องมือ: Next.js 16 · PostgreSQL (รันเองในเครื่อง/เซิร์ฟเวอร์) · auth เขียนเอง (bcrypt + JWT cookie) · เก็บไฟล์บนดิสก์เครื่องเดียวกัน · Cloudflare Tunnel (เปิดให้เข้าถึงจากอินเทอร์เน็ต) · Claude API

> โปรเจกต์นี้**ไม่ใช้ Supabase/Cloudflare Workers แล้ว** — ฐานข้อมูล ล็อกอิน และที่เก็บไฟล์ทั้งหมดรันเองบนเครื่อง/เซิร์ฟเวอร์ที่คุมเอง ส่วน Cloudflare ใช้แค่ Tunnel สำหรับเปิดพอร์ตให้เข้าถึงจากอินเทอร์เน็ตโดยไม่ต้องเปิด router เอง

> **รวมจาก v5** (รันซ้ำ `scripts/local_postgres_schema.sql` เพื่อเพิ่มตาราง `company_join` / `join_requests`): ลิงก์ชวนเข้าบริษัท + คำขอรอเจ้าของอนุมัติ (ตั้งค่า → สมาชิก) · สมัครเองได้เฉพาะมีลิงก์ชวน/คำเชิญ (หรือระบบยังไม่มีบริษัท) · สร้างบริษัทใหม่ได้เฉพาะเจ้าของ · บริษัทละเจ้าของคนเดียว · แยกสิทธิ์: สายทางและความยาวสายแก้ได้เฉพาะเจ้าของ, ราคา/เอกสาร/ใบกำกับภาษี/ไฟล์ใบสั่งจ้างเป็นของธุรการ (บัญชีเห็นแค่คนงาน ค่าแรง น้ำมัน) · ยังไม่มีลืมรหัสผ่านทางอีเมล (ไม่มีระบบส่งอีเมล)

> **อัปเดตฐานข้อมูลเดิม** (เคยติดตั้งรุ่นก่อน V.2): รัน `scripts/local_postgres_schema.sql` ซ้ำอีกครั้งกับฐานข้อมูลเดิม (รันซ้ำได้ ข้อมูลเดิมไม่หาย) — จะเพิ่มทะเบียนสายทาง ปีงบประมาณ คนงาน/ค่าแรง/รถ/น้ำมัน และช่องรูปตาม กม. ให้ แล้วรีสตาร์ทเว็บ

## ขั้นที่ 1 · ติดตั้ง PostgreSQL + สร้างฐานข้อมูล

1. ติดตั้ง PostgreSQL (เครื่องนี้ใช้เวอร์ชัน 18 ที่ `C:\Program Files\PostgreSQL\18\bin\psql.exe` — ถ้า `psql` ไม่อยู่ใน PATH ให้เรียกเต็ม path แบบนี้)
2. สร้างฐานข้อมูลเปล่าชื่อ `grass_cutting`
   ```bash
   "C:\Program Files\PostgreSQL\18\bin\createdb.exe" -U postgres grass_cutting
   ```
3. ติดตั้ง schema (รันครั้งเดียวตอนฐานข้อมูลว่าง)
   ```bash
   "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d grass_cutting -f scripts/local_postgres_schema.sql
   ```

## ขั้นที่ 2 · ตั้งค่า `.env`

```bash
cp .env.example .env
```

กรอก 3 ค่าใน `.env`:
- `DATABASE_URL` — เช่น `postgresql://postgres:รหัสผ่าน@localhost:5432/grass_cutting`
- `AUTH_SECRET` — ใช้เซ็น session cookie สร้างด้วย `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` (**ห้ามใช้ค่าตัวอย่าง ห้ามให้ใครเห็น เปลี่ยนแล้วทุกคนที่ล็อกอินอยู่จะหลุดออก**)
- `GEMINI_API_KEY` (ฟรี) และ/หรือ `ANTHROPIC_API_KEY` — ให้ AI อ่านใบสั่งจ้าง ไม่ใส่ก็ใช้งานได้ แต่ต้องกรอกสายทางเอง (ดูขั้นที่ 5)

## ขั้นที่ 3 · รันเว็บ

```bash
npm install
npm run build
npm run start                # http://localhost:3004 — โหมดโปรดักชัน ควรใช้ตัวนี้บนเซิร์ฟเวอร์จริง
```

รันไว้เบื้องหลังตลอดเวลาด้วย [pm2](https://pm2.keymetrics.io/) (กันไม่ให้ดับตอนปิดหน้าต่าง/restart เครื่อง):
```bash
npm install -g pm2 pm2-windows-startup
pm2 start node_modules\next\dist\bin\next --name grass-cutting --interpreter node -- start -p 3004
pm2 save
pm2-startup install          # ให้ pm2 เปิดเว็บเองตอนล็อกอินเครื่อง (Windows)
```
(บน Windows ใช้ `pm2 start npm ...` ไม่ได้ เพราะ npm เป็นไฟล์ .cmd จึงเรียก next ตรงๆ แทน)

## ขั้นที่ 4 · เปิดให้เข้าถึงจากอินเทอร์เน็ตด้วย Cloudflare Tunnel

ต้องมีโดเมนที่ผูกกับ Cloudflare อยู่แล้ว (เมนู DNS ขึ้นสถานะ Active)

1. ติดตั้ง [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)
2. ล็อกอินครั้งแรก (เปิดเบราว์เซอร์ให้เลือกบัญชี/โดเมน)
   ```bash
   cloudflared tunnel login
   ```
3. สร้าง tunnel (ทำครั้งเดียว)
   ```bash
   cloudflared tunnel create grass-cutting
   ```
   จะได้ไฟล์ credentials (`<tunnel-id>.json`) และ Tunnel ID — จดไว้
4. สร้างไฟล์ config เช่น `%USERPROFILE%\.cloudflared\config.yml`
   ```yaml
   tunnel: <tunnel-id>
   credentials-file: C:\Users\<ชื่อผู้ใช้>\.cloudflared\<tunnel-id>.json

   ingress:
     - hostname: grass-cutting.ตัวอย่างโดเมน.com
       service: http://localhost:3004
     - service: http_status:404
   ```
5. ผูกโดเมนเข้ากับ tunnel
   ```bash
   cloudflared tunnel route dns grass-cutting grass-cutting.ตัวอย่างโดเมน.com
   ```
6. รัน tunnel
   ```bash
   cloudflared tunnel run grass-cutting
   ```
   รันเป็น background service ตลอดเวลาด้วย `cloudflared service install` (ต้องรันบนเครื่อง/เซิร์ฟเวอร์เดียวกับที่รัน `npm run start`)

หลังจากนี้เข้าเว็บได้ที่ `https://grass-cutting.ตัวอย่างโดเมน.com` โดยไม่ต้องเปิดพอร์ต/ตั้ง port forwarding ที่ router เอง

> เว็บรันที่พอร์ต **3004** (ตั้งไว้ใน `package.json` ทั้ง `dev` และ `start`) · ถ้าสร้าง tunnel จากหน้า Cloudflare (ติดตั้งด้วย token แทนไฟล์ `config.yml`) ให้ตั้งที่ Cloudflare One → **Networks → Tunnels** → เลือก tunnel → **Public Hostname** → Service เป็น `http://localhost:3004`

## ขั้นที่ 5 · ใส่คีย์ AI (ให้ AI อ่านใบสั่งจ้างและรายชื่อสายทาง)

ไม่ใส่ก็ใช้งานได้ แต่ต้องกรอกสายทางเอง ใส่ได้ตัวเดียวหรือทั้งสองตัว ถ้ามีทั้งสองตัว ระบบจะใช้ Gemini ก่อน และถ้า Gemini อ่านไม่สำเร็จหรือโควตาเต็ม จะใช้ Claude แทนโดยอัตโนมัติ

**Gemini (ฟรี)**
- aistudio.google.com → **Get API key → Create API key** → คัดลอกคีย์
- วางค่าในช่อง `GEMINI_API_KEY` ของไฟล์ `.env` แล้ว restart
- free tier มีเพดานจำนวนครั้งต่อนาทีและต่อวัน และ Google อาจนำข้อมูลที่ส่งไปใช้ปรับปรุงบริการ ถ้าไม่ต้องการแบบนี้ให้เปิด billing ที่ Google หรือใช้ Claude แทน
- รุ่นที่ใช้ตั้งไว้เป็น `gemini-flash-latest` เปลี่ยนได้ที่ `GEMINI_MODEL`
- ไฟล์แนบที่ส่งให้ Gemini ได้ รวมกันประมาณ 14MB ถ้าใหญ่กว่านี้จะใช้ Claude แทน (ถ้ามีคีย์)

**Claude (เสียเงิน แม่นกว่า)**
- console.anthropic.com → **Settings → API Keys → Create Key** → คัดลอกคีย์ (ขึ้นต้น `sk-ant-`) และเติมเครดิตที่ **Billing**
- วางค่าในช่อง `ANTHROPIC_API_KEY` ของไฟล์ `.env` บนเครื่อง/เซิร์ฟเวอร์ที่รันเว็บ แล้ว restart (`pm2 restart grass-cutting`)
- ห้ามส่งคีย์นี้ในแชตหรือ commit ขึ้น git (`.env` อยู่ใน `.gitignore` แล้ว)
- ค่าใช้จ่ายโดยประมาณ 1–3 บาทต่อการอ่านใบสั่งจ้าง 1 ใบ

## ขั้นที่ 6 · เริ่มใช้

1. เปิดลิงก์เว็บ → **สมัครใช้งาน** (ล็อกอินเข้าทันทีหลังสมัคร ไม่ต้องยืนยันอีเมล — คนแรกที่สร้างบริษัทเป็น**เจ้าของ**)
2. สร้างบริษัท → กรอกหัวกระดาษ เลขผู้เสียภาษี บัญชีธนาคาร ผู้ลงนาม อัปโหลดโลโก้
3. แท็บ **แขวงและหมวด** → กด **ใช้ตัวอย่าง ขทช.ชลบุรี** หรือเพิ่มเอง
4. แท็บ **สมาชิก** → เชิญอีเมลพร้อมติ๊กบทบาท แล้วส่งลิงก์เว็บให้เขาสมัครด้วยอีเมลนั้น
5. เมนู **สายทาง** → เพิ่มสายในทะเบียน (พิมพ์เอง วางจาก Excel หรือให้ Claude อ่าน) แล้วไปเมนู **งาน** → **+ สร้างงวดแรก** → เลือกสาย → ได้ใบสั่งจ้างแล้วค่อยแนบ PDF ที่หมวดนั้น

## บทบาทและสิทธิ์

บทบาท (คนเดียวติ๊กได้หลายบทบาท ที่ ตั้งค่า → สมาชิก เฉพาะเจ้าของแก้ได้)

| บทบาท | ทำอะไรได้ | ไม่เห็น / ทำไม่ได้ |
|---|---|---|
| เจ้าของ | ทุกอย่าง เชิญ/แก้/นำสมาชิกออก ย้ายข้อมูล | – |
| ธุรการ | ใบสั่งจ้าง สายทาง แขวง ข้อมูลบริษัท ใบเสนอราคา หนังสือส่งมอบ ร่างใบกำกับภาษี/ใบเสร็จ | ค่าแรง น้ำมัน · ออก/ยกเลิกใบกำกับภาษี |
| บัญชี | ค่าแรง รายชื่อลูกจ้าง ใบสำคัญจ่าย น้ำมัน ต้นทุน ออก/ยกเลิกใบกำกับภาษี/ใบเสร็จ ดูเอกสารทั้งหมด | แก้ใบสั่งจ้าง · ทำใบเสนอราคา/หนังสือส่งมอบ |
| หัวหน้าชุด | บันทึกรายวัน (ติ๊กคนมา สายทาง กม. ค่าน้ำมัน) รูปก่อน/หลัง สถานะและความยาวสาย รายงานภาพถ่ายต่อสาย | ราคา มูลค่า ค่าแรง เอกสาร |
| ดูอย่างเดียว | เห็นงวด สายทาง รูป ความคืบหน้า | แก้อะไรไม่ได้ ไม่เห็นเงิน |

- **ขอบเขตงาน**: หัวหน้าชุด/ดูอย่างเดียว จำกัดให้เห็นเฉพาะบางแขวงหรือบางหมวดได้ (ไม่ติ๊ก = เห็นทั้งหมด)
- หัวหน้าชุดบันทึกรายวันได้แต่ไม่เห็นค่าแรง ระบบใส่ค่าแรงตามรายชื่อลูกจ้างให้เอง คนที่เพิ่มเฉพาะวันนั้นใช้ค่าแรงตั้งต้น ฝ่ายบัญชีแก้ทีหลังได้ · สายที่อยู่นอกขอบเขตของหัวหน้าชุดคนนั้นในวันเดียวกันจะไม่หาย
- ลบบันทึกรายวันได้เฉพาะบัญชี/เจ้าของ
- สิทธิ์ตรวจที่ชั้นเซิร์ฟเวอร์ (TypeScript, `src/lib/data/perm-db.ts`) ทุกครั้งที่อ่าน/เขียนข้อมูล ไม่ใช่แค่ซ่อนปุ่มฝั่งหน้าเว็บ — ฟิลด์ที่ไม่มีสิทธิ์เห็น (เช่น ค่าแรง/ราคา) ถูกตัดออกก่อนส่งให้หน้าเว็บเสมอ
- ข้อจำกัด: บันทึกรายวันยังเป็น 1 ใบต่อบริษัทต่อวัน ถ้ามีหลายชุดทำงานวันเดียวกัน รายชื่อคนมาจะรวมอยู่ใบเดียว

## ใช้งานอะไรได้บ้าง

- **หน้าหลัก** งานค้าง งวดปัจจุบัน และตัวเลขสรุป · เมนูมีตัวเลขเตือน (เอกสารที่ควรทำ ใบสั่งจ้างที่ค้าง ค่าแรงรอจ่าย)
- **สายทาง** ทะเบียนสายทาง แขวง › หมวด › สาย (เลขสาย ชื่อ อำเภอ ความยาว กม. ลิงก์แผนที่)
- **งาน** งวด = แขวง + ปีงบ + งวดที่ แต่ละหมวดเป็นใบสั่งจ้าง 1 ใบ เลือกสายจากทะเบียนเป็นแผนก่อน แล้วค่อยแนบใบสั่งจ้างทีหลัง · สายที่อยู่ในแผนแต่ไม่อยู่ในใบสั่งจ้างไม่ขึ้นในเอกสาร
- **หน้าสายทาง** รูปรายงานตาม กม.
  - ก่อน/หลังตัด ทุก 500 ม. และแบบสำรวจซ้าย/ขวาทาง ทุก 250 ม. (เปิดต่อแขวงที่ ตั้งค่า → แขวงและหมวด)
  - อัปโหลดรูปลง **ถาด** ก่อน (ย่อเหลือ 1600px อ่านวันเวลาถ่ายจากรูป รูปซ้ำข้ามให้) แล้วกดรูป → กดช่อง หรือลากไปวาง · ปุ่มเติมรูปแค่เสนอ ต้องกดยืนยันเอง
  - รูปครบทุกช่องถือว่ารูปครบ · สถานะสาย (ตัดแล้ว/วันที่จบ) มาจากบันทึกรายวัน
- **บันทึกรายวัน** ติ๊กคนมา/ครึ่งวัน/ไม่มา สายที่ตัด กม. จบสาย ค่าน้ำมัน บันทึกอัตโนมัติ
  - กม. ใช้ดูความคืบหน้าเท่านั้น ไม่เกี่ยวกับ ตร.ม. ที่คิดเงินและออกเอกสาร
- **คนงานและค่าแรง** ทะเบียนคนงาน เบิกล่วงหน้า จ่ายรายสัปดาห์ (จ่ายแล้ววันของคนนั้นล็อก) **ใบสำคัญจ่ายค่าแรง (PDF)** · ทะเบียนรถและเบิกน้ำมัน
- **ใบสั่งจ้าง** ตาราง งวด × หมวด ต่อแขวง เห็นว่างวดไหนค้างเอกสารหรือรอออกใบกำกับ
- **เอกสาร** บอร์ดตามหมวด กดสร้างเอกสารต่อหมวดได้เลย + ทะเบียนเอกสาร
  - ใบเสนอราคา (GQT) · หนังสือส่งมอบงาน (GDL จัดให้พอดี 1 หน้าเอง) · ใบกำกับภาษี/ใบเสร็จ (GRC) เลขที่รันเองตามปี บันทึกอัตโนมัติ ย้อน/ทำซ้ำได้ (Ctrl+Z)
  - ใบกำกับภาษีที่ออกแล้วแก้ไม่ได้ ต้อง **ยกเลิกเอกสาร** (ใส่เหตุผล) แล้วกด **ทำฉบับใหม่จากใบนี้** · ลบได้เฉพาะฉบับร่าง
- **PDF** รายงานภาพถ่ายต่อสาย (แบบ ก่อน/หลัง 500 ม. และแบบสำรวจ 250 ม.) · ใบสรุปงวด · ชุดส่งงวด (สรุป + รูปทุกสาย)

## ย้ายไปเครื่องอื่น

มีสคริปต์ใน `scripts\move\` (Windows) ย้ายฐานข้อมูล ไฟล์แนบใน `storage\` และ `.env` ให้ครบ

**เครื่องเดิม** (ในโฟลเดอร์โปรเจกต์) — หยุดเว็บ (pm2) แล้วสร้างโฟลเดอร์ `move-package` ที่มี `grass_cutting.dump`, `storage.zip`, `.env`, `manifest.txt`
```bash
scripts\move\export-data.cmd
```
คัดลอกโฟลเดอร์ `move-package` ไปเครื่องใหม่ (มีรหัสผ่านใน `.env` ห้ามส่งในแชตหรืออัปขึ้นที่สาธารณะ)

**เครื่องใหม่** — ติดตั้งโปรแกรม แล้ว clone โปรเจกต์
```bash
winget install OpenJS.NodeJS.LTS Git.Git PostgreSQL.PostgreSQL.18 Cloudflare.cloudflared
```
```bash
git clone https://github.com/it549/Grass_Cutting.git grass-cutting
```
ถ้ารหัสของ user `postgres` บนเครื่องใหม่ต่างจากเดิม ให้วาง `.env` ไว้ในโฟลเดอร์ `grass-cutting` แล้วแก้ `DATABASE_URL` ก่อน จากนั้นรัน (ใน cmd แบบ Run as administrator ถ้าจะให้ติดตั้ง tunnel ด้วย):
```bash
scripts\move\import-data.cmd -From D:\move-package -TunnelToken <token จาก Cloudflare One → Networks → Tunnels>
```
สคริปต์จะ restore ฐานข้อมูล อัปเดต schema เทียบจำนวนแถวกับเครื่องเดิม แตกไฟล์แนบ build และรันเว็บด้วย pm2 ที่พอร์ต 3004 · ถ้าเครื่องใหม่มีข้อมูลอยู่แล้วจะหยุดก่อน (ใส่ `-Force` ถ้าตั้งใจทับ) · ไม่ใส่ `-TunnelToken` ก็ได้ แล้วติดตั้ง tunnel เองทีหลัง

**เสร็จแล้ว** ถอน tunnel และหยุดเว็บบนเครื่องเดิม ไม่อย่างนั้น Cloudflare อาจส่งผู้ใช้ไปเครื่องเก่า:
```bash
cloudflared service uninstall
```
```bash
pm2 delete grass-cutting
```

## สำหรับนักพัฒนา (รันในเครื่อง)

```bash
cp .env.example .env         # ใส่ DATABASE_URL, AUTH_SECRET, ANTHROPIC_API_KEY
npm install
npm run dev                  # http://localhost:3004
```

โครงสร้าง
- `scripts/local_postgres_schema.sql` ติดตั้งฐานข้อมูลใหม่ครั้งเดียว (ตาราง + ฟังก์ชัน/ทริกเกอร์ที่ไม่ขึ้นกับ "ใครเรียก" เช่น `next_doc_no`, `save_order`)
- `src/lib/db/sql.ts` — SQL client ตัวเดียว (`postgres` / porsager) ที่ทุกไฟล์เรียกใช้
- `src/lib/auth/` — auth เขียนเอง: `password.ts` (bcrypt), `session.ts`/`jwt.ts` (เซ็น/ตรวจ JWT เก็บใน httpOnly cookie `gc_session`), `proxy.ts` (ต่ออายุ session ใน `src/proxy.ts` โดยตรวจแค่ JWT ไม่ query ฐานข้อมูล)
- `src/lib/data/` — ฟังก์ชันที่ต้องรู้ว่า "ใครเรียก" (`createCompany`, `saveDaily`, `setRouteStatus`, …) รับ `userId` ตรงๆเป็น parameter + `perm-db.ts` (ตรวจ/กรองสิทธิ์)
- `src/lib/data/views.ts` — แทน view เดิมของ Supabase (`routes_v`, `crew_v`, `daily_v`, `crew_pays_v`): กรองตามขอบเขตแขวง/หมวด และซ่อนราคา/ค่าแรง/ยอดเงินตามบทบาท
- `src/lib/context.ts` ผู้ใช้ปัจจุบัน + บริษัทที่เลือก (คุกกี้ `gc_company`)
- ไฟล์แนบ (รูป/โลโก้/PO) เก็บใต้ `storage/company-files/<company_id>/...` บนดิสก์เครื่องที่รันเว็บ (ไม่ sync ไปที่อื่น) — อ่านผ่าน `src/app/api/files/[...path]/route.ts`, อัปโหลดผ่าน `src/app/api/files/upload/route.ts` ทั้งสองตรวจสิทธิ์ก่อนเสมอ
- `src/app/(app)/settings/*` หน้าตั้งค่า
